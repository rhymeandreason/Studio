# Notes

`notes.json` per project; `state.notesData` in memory, `renderNotes()` fully re-renders. Kinds: `text` / `checklist` / `table` / `image`.

**Images:** Image notes use `note.src`; text notes can have one optional `note.image` (both project-relative `notes/<id>.<ext>`, never base64). `note.imageW`/`imageH` reserve aspect ratio. Paste (Cmd+V) into a focused text note textarea to attach above the body; hover to reveal ×. Deletion cleans up the asset.

**Styling:** Per-note theme/font/span as scoped CSS variables on the card, overriding the list-level `--notes-font`/`--notes-font-size` defaults on `.notes-list` (static since the project-wide font picker was removed; `notesData.font`/`fontSize` in older `notes.json` files are ignored). `notesData.viewMode` (`"bento"`, `"days"` or `"tags"`) is persisted. Tags view groups by tag (a multi-tagged note appears under each, so drag-*reorder* is off there — `onNotePointerDown`'s `canReorder`; Option-drag-out still works in every view) with "Untagged" last, and reuses the days-view single-file layout.

**Tags:** optional `note.tags` (string array) on any kind. No registry — the project's vocabulary is derived from the notes (`allTags()`), so the last note to drop a tag retires it. Chips live on a wrapped second line of the card footer; the `+` and the chip `×` only show on card hover. `t` on a card selection opens the input on the first selected card and applies the commit to the whole selection (comma-separated = several tags). `#notes-filter-bar` is a wrapping row of chips (one per in-use tag, with counts) living on its own line *inside* `.notes-toolbar`, so it inherits the toolbar's sticky + background treatment and stays reachable as the list scrolls under — always on show, no toggle button, and not a dropdown (which would clip at the window edge when narrow). It collapses to nothing until the project has a tag. One tag at a time (`notesFilter` is a string or null) — a chip replaces the current filter, clicking the active one clears it. Every note-creation path calls `clearFilterForNewNote()`: a brand-new note has no tags, so a live filter would swallow it on the spot. The filter is module-local, cleared on project switch and never persisted; while it's active — as in tags view — drag-reorder is off, since the rendered-card index no longer maps to an index in `notes`. Markdown export appends a `#tag` line; copy/paste carries tags via the normal spread in `stripNoteForCopy()`.

**Markdown export / linked notes:** the toolbar `markdown` button writes `<title>.md` to the project root (`noteToMarkdown()`) and hands it to `open_file_in_code_editor` — the same Rust command the File Directory uses.

A **text** note additionally gets `note.mdFile` (project-relative) and becomes a *linked* note: the file is the source of truth from then on, and `buildLinkedNote()` renders it read-only through the vendored `marked` (filename chip → Code Editor, `link_off` → unlink, which hands the text back and makes the note editable again). Other kinds stay a one-shot dump — they can't round-trip through Markdown without losing their structure. `note.body` is kept as a cache of the file text so copy/export/plain-text work without touching disk; `mdCache` (path → text, `null` = missing) backs the render. Files are re-read per card build and by `refreshLinkedNotes()` on window focus, since the edits happen in the Code Editor window. Re-exporting a linked note just opens it (rewriting would clobber those edits), and `stripNoteForCopy()` drops `mdFile` so a pasted copy is a plain note. Deleting a linked note never deletes its `.md` — the file is a document in the project, not an asset the card owns.

**Layout:** `layoutBento()` measures card heights and sets row-spans — re-pack on any height change, and after the panel becomes visible (hidden elements measure 0).

**Copy/paste:** Studio-native payload via app-cache sidecar (the `note-clipboard` store via `read_store`/`save_store`) keyed to clipboard text — WebKit strips custom HTML flavors.
